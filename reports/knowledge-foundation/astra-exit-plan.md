# Astra的关键职责与合理分工

2026-09-22，按用户最新说明替代此前“退出条件”方案。目标是把Astra投入到有明显质量收益的工作；不建立脱离Astra实验，不要求Astra先做完所有文章，也不以复杂评估阻塞任务。

| 工作 | 先由谁做 | Astra负责什么 |
| --- | --- | --- |
| 核心知识 | 脚本提取；其他模型整理来源、候选定义、别名、依赖和冲突 | 统一概念边界、消除冲突、决定核心先修与解释深度，形成共享定稿 |
| 前端审美 | 其他模型按既有组件实现和运行检查 | 关键模板的布局、视觉层次、阅读连续性和交互取舍；修一次供文章复用 |
| 规则与标准 | 其他模型归并已有规则、找重复与缺项 | 确定少量关键规则和实质质量门，避免矛盾和过度约束 |
| 逐篇生产准备 | 其他模型按规则填文章类型、目标、必要概念、示例和缺项；脚本装配 | 仅审真正影响共享知识或教学判断的异常，不逐篇代填 |
| 翻译、校正、排版、常规检查 | 其他模型和脚本 | 不作为日常必经环节；不默认代修或兜底 |

每次给Astra分配任务前，只做一次直接判断：这是否需要Astra的优势？其他模型按现有材料完成，质量是否会明显不同？若没有明确收益，就交给其他模型或脚本。无需用对照实验来回答常规分工问题。
