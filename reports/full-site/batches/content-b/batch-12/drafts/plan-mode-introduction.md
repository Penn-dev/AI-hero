**更新**：这篇文章写于 2026 年 1 月，我的想法后来变了。我已经不再用计划模式：它问的澄清问题不够多，太快下结论，又急着生成一份材料，结果是一份大多数人都不读的超长计划。现在，我只把智能体当同事一样交谈。用的工具是 [/grill-with-docs 技能原文](https://www.aihero.dev/skills-grill-with-docs)，也可查看[中文技能页](/skills-grill-with-docs)。它会围绕你想构建的东西展开访谈，并边问边记录决定。本文的核心观点仍然成立：写代码前，先和智能体把方向对齐。但现在，我用深入追问的方式来做到这一点。

本文写给用过 AI 编程智能体、却对结果感到失望的人。

如果你觉得 AI 智能体生成的代码质量差，或者它不理解代码库，就该试试计划模式。

在计划模式里，写任何代码之前，你先和智能体一起反复梳理要构建什么：讨论需求、验证假设、打磨方法。智能体会探索代码库，建立上下文。开始编码时，它就知道具体该做什么，也有了所需信息。

本文一直用 [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview) 举例，因为我最初就是在这里接触计划模式的。不过，其他 AI 编程工具也加入了类似功能，是否支持可以查阅各自文档。

## 什么是计划模式

启动 Claude Code 时加入 `--permission-mode plan`，或者在会话中输入 `/plan`，就会进入一种受限模式：

| 操作 | 计划模式是否允许 |
| --- | --- |
| 读取文件 | 是 |
| 探索代码库 | 是 |
| 分析代码 | 是 |
| 编辑文件 | 否 |
| 运行命令 | 否 |
| 执行测试 | 否 |

智能体会探索仓库、提出澄清问题，并输出逐步计划。你满意后，就退出计划模式，让它执行。

**我几乎所有事情都用计划模式**，连小缺陷修复也不例外。关键在于，它会验证我的假设，在把任何决定落实成代码之前，帮助我不断靠近正确方案。

## 计划模式下的编程循环

循环很简单：

1. 用口述说出需求。可以很概括，例如 “add user auth”（添加用户身份验证）；也可以很具体，例如 “refactor `handleSubmit` in `LoginForm.tsx`”（重构 LoginForm.tsx 中的 handleSubmit）。
2. 进入计划模式。
3. 持续迭代，直到智能体给出你满意的计划。
4. 退出计划模式，让智能体执行。

中文版 Prompt（学习辅助，对应上面的概括需求示例）：

```text
添加用户身份验证。
```

中文版 Prompt（学习辅助，对应上面的具体需求示例）：

```text
重构 LoginForm.tsx 中的 handleSubmit。
```

对于大型功能，你可能会先花一小时规划，然后才开始写代码。

通常不会在规划与执行之间清空上下文窗口。这样，执行开始时，智能体已经有了规划阶段读过的文件和相关上下文。这正是计划模式有效的原因：它不只是生成一份计划文档，更是在提前准备智能体的上下文。

例外是多阶段计划：把大型功能拆成多个独立的规划/执行循环。这超出本文范围，但掌握基本循环后，值得进一步探索。

## 一定要用语音输入

**如果你与 AI 协作时还不用语音输入，就落后了**。口述可以让你比用其他输入方式更快地表达想法。

我在 Windows 上使用 [Wispr Flow](https://wisprflow.ai/)，Mac 上的 [Superwhisper](https://superwhisper.com/) 也很好。

关键在于：AI 不需要语法完美的输入。尤其在计划模式里，智能体反正会重写你的 Prompt。所以，凌乱、想到哪说到哪的口述也没问题。一旦智能体把它们整理成计划，对话最上方那些不合语法的输入就不重要了。

## 计划模式怎样帮助智能体

智能体只能利用上下文窗口里的内容。没读过文件，就无法很好地修改；不了解项目结构，就会误判内容应该放在哪里。

计划模式会在**写任何代码之前先建立上下文**。智能体探索代码库，读取要修改的文件，发现各部分之间的关系。退出计划模式时，它已经加载了所需内容。

计划文档本身也很重要。它为执行提供明确的步骤，而不是让智能体边做边猜。已有文件上下文，再加上显式步骤，可以排除许多出错方式。当智能体清楚自己在处理什么、需要做什么时，代码质量就会明显提升。

## 计划模式怎样帮助开发者

在看到结果之前，你并不真正知道自己想要什么。客户如此，你也一样。别骗自己说开始前已经完全想清楚了。你没有。

**计划模式让你在动代码前先推敲方案**。你和智能体一起迭代要做的东西：讨论取舍、验证假设、发现边界情况，整个过程都发生在第一行代码出现之前。这与你和同事讨论的过程一样，只是更快。

计划模式会迫使需求变得具体。你不会把模糊需求丢给人类同事，然后期待得到好结果；不用计划模式时，你对 AI 做的恰好就是这件事。维护过开源仓库、费力辨认过模糊报错截图的人，肯定明白我在说什么。

计划模式迫使你把需求讲清楚，清楚到另一个人也能实现。很多时候，解释的过程还会让你发现：自己真正想要的，其实略有不同。

## 怎样在计划模式里写出更好的 Prompt

你可以通过项目根目录中的 [AGENTS.md](https://agents.md) 文件，自定义 Claude Code 的行为。以下建议有助于提高计划模式的效果。

> 译注：原文把 AGENTS.md 作为行为配置文件来介绍，未提供具体工具版本或加载方式。本文保留名称，不替读者假定文件已经被所用工具读取。

### 让计划简洁

计划不该写成小说。告诉智能体，为了简短可以牺牲语法完整性。这样更容易扫读，也能聚焦重点。

```markdown
When writing plans, be extremely concise. Sacrifice grammar for the sake of concision.
```

中文版 Prompt（学习辅助）：

```markdown
写计划时要极其简洁。为了简洁，可以牺牲语法完整性。
```

### 让规划者提出澄清问题

智能体默认会问一些问题，但你可以要求它问得更全面，在模糊之处变成缺陷前就找出来。

```markdown
At the end of each plan, list unresolved questions. Ask about edge cases, error handling, and unclear requirements before proceeding.
```

中文版 Prompt（学习辅助）：

```markdown
每份计划结尾都列出未解决的问题。继续之前，先询问边界情况、错误处理和不明确的需求。
```

### 把总结放在最后

在终端里，你会先看到输出末尾。让智能体把可执行的总结放在最后，就不必向上滚动查找。

```markdown
End every plan with a numbered list of concrete steps. This should be the last thing visible in the terminal.
```

中文版 Prompt（学习辅助）：

```markdown
每份计划都以带编号的具体步骤清单结尾。它应该是终端里最后显示的内容。
```

## 这不是比我自己写还慢吗

有时确实如此。如果你对仓库了如指掌，立刻就能看出解法，不用 AI 可能更快。

但计划模式的意义，不只是在熟悉领域里追求速度，它还能扩展你的能力范围。面对不熟悉的代码库，或者需要先想清楚需求再动手时，计划模式至关重要。它让你能参与以前无法胜任的工作。

**我做任何事都用计划模式，即使确信自己写会更快**。原因有三点：

1. **工具一直在进步**。速度正是改善最快的方面之一。每次使用计划模式，我都会更了解 AI 能处理什么，以及怎样向它表达需求。这种能力会不断累积。
2. **更不容易疲惫**。与修语法错误、追查类型不匹配相比，专注于高层决策耗费的精力更少。我能做得更多，也没那么累。
3. **AI 是我遇到过最好的“小黄鸭”**。它能迅速理解代码库，全天候可用。计划模式迫使我清楚表达需求，也让我更擅长构建软件。开始使用后，我的代码质量和产出都提高了。

问题不该是“眼下是不是更慢”，而是“我到底在优化什么”。如果你追求的是学习、减少疲劳和长期效率，那么即使你独自写代码在技术上更快，计划模式仍然更值得。

## 结语

计划模式不是可有可无的选项，而是 AI 辅助编程的一项基础工具。

1. **所有事情都用计划模式**，包括小缺陷修复
2. **使用语音输入**，AI 不需要完美语法
3. **配置 AGENTS.md**，让计划简洁，并在结尾提出问题
4. **规划帮助智能体**，让它先建立上下文再写代码
5. **规划帮助你**，迫使你把需求说清楚
6. **眼下不一定总是更快**，但它是对长期能力的投资
