# 中文学习页的术语与辅助展示

2026-09-22，按系统提示词页的实际反馈确定。后续生产复用此规则；不要求本轮改完历史页面。

- 有自然、稳定译名的概念，正文以中文为主，例如系统提示词、执行框架、前缀缓存。首次正式解释核心概念时附英文，后文用中文或已说明的简称；不在每次出现时重复双语。
- 中文技术语境常直接使用的名称、缩写和文件名保留原名，例如 Token、LLM、API、SDK、MCP、Git、Markdown、AGENTS.md。需要时解释含义，不机械替换成生僻中文。代码标识符保持原样。
- 术语解释的标题采用“中文（英文）”；约定保留原名的词只写原名，避免 Token（token）、Markdown（Markdown）这类重复。缩写与中文全称都需要保留时，可采用“大语言模型（LLM）”。搜索始终覆盖中文、英文和别名，与标题展示分离。
- harness 在本项目首次正式解释写“智能体执行框架（harness）”，后文可写“执行框架”；术语解释保留完整双语名称。system prompt 写“系统提示词（system prompt）”，不以英文替代正文中的自然中文表达。
- 不是所有普通词都在正文中加英文。可在术语解释查到英文的模型、工具、会话等，不为了形式统一而给每句话堆括号。拿不准且会影响理解或跨篇一致性的词，再集中讨论。
- 原始示例与中文理解紧邻呈现；对话按“一句英文原例＋对应中文理解”成对排列。新增中文学习辅助放在完整示例之后，不插到原例与译文之间。必须标明新增辅助身份，但不要求所有辅助使用同一种卡片。
- 比较卡片按实际条目布局；两列中的单数尾卡占满整行，窄屏单列，不留下没有语义的空白占位块。
- 已配置解释的术语，点击词本身打开本页释义，旁边独立的 ↗ 只跳已有中文页。尚未翻译但值得保留的目标记录到待翻译清单，当前不跳英文或空页面；没有中文学习价值的目标不提供跳转。源文中的概念链接必须核对本地解释覆盖；缺失应在生产校验中报告，不能把可跳原页当成已经提供了零基础解释。此要求不等于全站每一个词都需制成词条。
- 自检问答使用独立的 question 和 answer 字段，由模板分别显示“问”“答”。生产者负责内容，脚本负责排版，不把问答拼成一行再要求编辑调整样式。
