“幻觉”是指[模型](/ai-coding-dictionary/model)以肯定语气给出的错误内容。它可以分为两类，两者的成因和处理方法并不相同：

| 类型 | 出了什么问题 | 原因 | 处理方法 |
| --- | --- | --- | --- |
| _事实准确性（Factuality）_ | 编造或弄错了现实世界中的事实，例如不存在的函数、错误的 API 调用格式或虚假的引用来源 | [参数知识](/ai-coding-dictionary/parametric-knowledge)存在空缺，尤其容易发生在[知识截止时间](/ai-coding-dictionary/knowledge-cutoff)之后的信息上 | 加载正确的[上下文知识](/ai-coding-dictionary/contextual-knowledge) |
| _忠实性（Faithfulness）_ | 输出偏离了已经加载的上下文知识、用户指令，或模型自己此前的推理 | [注意力衰减](/ai-coding-dictionary/attention-degradation)；进入[低效区](/ai-coding-dictionary/smart-zone)后会更加严重 | [清空](/ai-coding-dictionary/clearing)或[压缩](/ai-coding-dictionary/compaction) |

[下一个 Token 预测](/ai-coding-dictionary/next-token-prediction)无论依据的事实是否真实，都能生成流畅的内容。模型内部没有一个信号能明确告诉它“我不知道”，所以编造出来的方法名也会和正确的方法名一样，以十分肯定的语气出现。出现幻觉的代码之所以看起来可信，正是因为它通常很像“如果这个 API 真的存在，本来应该有的样子”。这类错误很容易躲过匆匆浏览式的审查，直到代码实际运行时才暴露。

必须先判断遇到的是哪一类幻觉，因为解决一类问题的方法，可能会加重另一类问题。事实准确性问题说明模型缺少知识，应该补充上下文，例如文档、类型定义或相关文件。忠实性问题则说明正确知识已经在上下文中，只是在争夺模型注意力时被忽略了，此时应该减少上下文。如果把忠实性问题误判成事实准确性问题，继续粘贴更多文档，只会让上下文更长、偏离得更严重。智能体答错时，应先检查正确信息是否已经在上下文中，再判断是哪种问题。

_避免使用：_不要笼统地把所有“错误”都称为“幻觉”——如果不说明是哪一类，这个词就无法帮助你诊断原因。

_用法：_

“它凭空说这个 schema 有一个 `parseAsync` 方法。”

“是事实准确性问题，还是忠实性问题？”

“这个方法就在我粘贴的文档里——只是到了第 40 个[工作轮次](/ai-coding-dictionary/turn)，它就不再参考那些文档了。”

“那就是忠实性问题。先压缩上下文，再重新加载；不用继续添加文档。”

## 中文学习辅助：术语小词典

- **hallucination**：幻觉，模型用肯定语气给出错误或凭空编造内容的现象。
- **Factuality**：事实准确性，指模型说出的事实本身是否真实、正确。
- **Faithfulness**：忠实性，指模型的输出是否忠于已经提供给它的资料、指令和推理过程。
- **attention degradation**：注意力衰减，指上下文变长或干扰增多后，模型更容易忽略其中重要信息的现象。
