选对模型，会直接影响 AI 应用能否成功。但这个决定并不好做。

它涉及许多层面，而且不是做一次就结束。随着新模型出现、应用不断发展，你需要**一遍又一遍地重新选择**。

我把这个决定拆成了几个关键问题，选模型时需要逐一问问自己。

译注：本篇保留 2025 年 3 月固定原文的分类、厂商例子和市场判断。原文中的“目前”、价格趋势、性能排名及上下文大小没有在本次重新核实，不应当作当前购买或选型结论。

## 1. 应该使用开放模型还是封闭模型？

主要有两类模型可供选择：**开放模型**和**封闭模型**。

### 开放模型

开源模型可以免费下载和使用。不过，如果想用它们构建应用，你就需要自己托管和运行。

开放模型既可以在自己的硬件上运行，也可以放在 AWS、Azure 等云服务上。

想找开放模型，可以看看 [Open LLM Leaderboard](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard#/)。

译注：本节按原文使用“开放”和“开源”的说法；具体模型是否允许某种使用方式，仍取决于其许可证。后文也会介绍由第三方 API 提供商托管开放模型的选择，因此“自己托管”不是本篇唯一提到的使用路径。

### 封闭模型

闭源模型由公司控制。你需要付费使用，但由公司托管，不必自己操心怎样运行。

目前世界上最强大的模型是闭源的，不过开放模型也一直在进步。

[Chatbot Arena](https://lmarena.ai/?leaderboard) 是比较开放与封闭模型的一个好地方。

### 模型提供商、API 提供商与自行托管

有两类公司会托管模型，供你调用：

**模型提供商**使用闭源模型。你付费使用它们的模型，模型由公司托管。这类公司包括 OpenAI、Google、Anthropic、Deepseek 等。

**API 提供商**托管开源模型，并按使用收费，例如 Hugging Face、Groq 等。

你也可以自己托管模型。这最灵活，但也最昂贵。你需要支付运行模型的硬件费用，还要负责让它持续正常运行。

译注：API 是应用向服务发请求的接口。这里的两类公司是作者为解释托管方式所作的划分，具体公司和模型未在本次逐一核验；不要仅凭这份示例名单推断某家公司所有模型的开放许可情况。

## 2. 成本是多少？

模型是否由你自己托管，会影响付费方式。

### 按 Token 计费

大多数模型提供商按 Token 收费。用得越多，付得越多。最常见的标价方式是“每百万 Token 的费用”。

不只是输入 Token，也就是你发给模型的内容，要收费；补全 Token，也就是模型回复的内容，同样要收费。

这是传统的按用量计费模式，就像 serverless 平台按计算时间收费一样。Token 可以大致衡量你使用了多少模型能力。

为了争夺市场份额，各家公司正在全球范围内竞相压低 Token 价格。[Helicone](https://www.helicone.ai/llm-cost) 这样的比价网站有助于比较费用。

译注：补全 Token 在这里就是输出 Token。原文没有列出固定价目，本页也没有增加未经核实的新价格。

### 托管开源模型

自己托管开源模型可能更划算。此时，你不再按 Token 付费，而是为模型托管支付固定费用。

另一个好处是，你可以完全掌控自己的数据。这对数据存放地点和隐私要求可能很重要。

不过，模型需要性能强大的硬件，这也可能很贵。你要权衡自行托管和使用模型提供商的成本。

我通常建议先从第三方 API 开始。它们最灵活，成本也比较合理；之后如果需要，再改为自行托管。

## 3. 延迟有多重要？

另一个需要考虑的特性是**延迟**，也就是模型回复一个查询大致需要多长时间。许多用途非常依赖快速响应，更快的回复也能让应用对用户更有用。

延迟受**模型规模**影响。较小的模型运行更快，但通常也不那么准确。

模型运行所在的**硬件**也会影响延迟，更强的硬件可以更快地运行模型。

最后，**推理优化**也会影响延迟。这类优化会加快模型的推理过程，包括量化、蒸馏和并行处理，具体细节超出了本文范围。

译注：推理是运行模型来生成结果。量化通常用更低精度表示数值，蒸馏让较小模型学习较大模型的表现，并行处理则把计算分配到多个执行单元。这些只是帮助理解名称的简短说明，本页没有提供优化操作教程。

### 衡量延迟

衡量延迟时，主要看两个指标：

- **TTFT，首个 Token 的等待时间**：模型多久开始生成回复。
- **TPOT，每个输出 Token 所需时间**：模型生成每个 Token 要多久。

## 4. 怎样评估模型表现？

成本和延迟很重要，但如果模型做不了你需要的任务，那它就没有用。

一般来说，较小的模型表现更差。参数越少，能用来存放信息的空间也越小。

### 公开基准测试

模型表现是个非常难以捉摸的指标。比较两个模型，然后断定谁更好，极其困难。

模型提供商和开源项目常用的一种方法，是基准测试。这些标准化测试会衡量模型在特定任务上的表现，例如翻译、总结、问答或编程。

基准测试能提供不错的初步参考。但模型过度适应这些测试的风险一直存在。可能是预训练时无意读到了测试数据，也可能是组织内部提高分数的压力导致的。

译注：过度适应测试，是指模型特别擅长某套考题，却未必能同样做好新的真实任务。这也是不能只看榜单名次的原因。

有些基准会让模型互相比较，由人类判断哪个输出更好。[Chatbot Arena](https://lmarena.ai/?leaderboard) 就是一个例子，值得作为模型表现的初步参考。

### 专用模型

有些模型在特定任务上表现更好，通常与训练数据有关。如果看过大量代码示例，模型就更擅长编程。翻译、分类、总结等许多领域也是如此。

如果你的任务很专门，值得找找针对它的专用模型。这些模型通常比通用模型表现更好，也往往更小，因此运行更快、效率更高。

### 推理模型

有些模型被专门设计成先停下来思考，再给出回复。这就是**推理模型**，这股趋势由 OpenAI 的 o1 开始。

这类模型通常更擅长需要提前规划和批判性思考的任务，比如编程和数学题。它们还会用推理 Token 输出规划过程，可以实时流式展示给用户。

不过，它们通常比普通模型更贵，回复也更慢。这是在表现和延迟之间做取舍。

译注：上面的推理过程展示是原文概括，没有核实具体接口。实际产品可能只提供摘要、用量统计或不提供可见推理文本，不能把这里理解为所有模型都可读取完整内部过程。

### Evals

真正评价一个模型，只有把它放进自己的应用中测试。因此，为系统建立评估非常重要。

[Evals（评估）（中文）](/what-are-evals)（[英文原文](https://aihero.dev/what-are-evals)） 是一组在你自己的系统上运行的测试，用来观察系统随时间是在变好还是变差。后面我们会详细介绍。

## 5. 需要多大的上下文窗口？

上下文窗口指模型一次能看到多少 Token。窗口越大，模型生成下一个词时能用到的信息就越多。

这个上限以 Token 计算，同时包含输入和补全 Token。输入太长，或者让模型生成太长的回复，可能触发 API 错误，或者让它无法生成回复。

上下文窗口大小与模型生成文本的机制有关，因此与模型自身的设计相关。窗口大小一直在增长。目前，Gemini 模型拥有最大的上下文窗口。

所有模型的上下文都有上限，因此管理它是 AI 工程师一直要面对的问题。RAG 中的分块等做法，就是为了把更多有用信息放进上下文窗口。

译注：RAG 是检索增强生成，先从资料中找出相关内容，再交给模型回答；分块是把大份资料拆成较小片段。“Gemini 最大”属于原文当时的判断，本页没有核实最新排名。

## 总结

选模型时，需要考虑这五个因素：

- 开放还是封闭。
- 成本。
- 延迟。
- 表现。
- 上下文窗口。

榜单和基准测试是不错的起点。但要真正判断一个模型是否适合你的应用，唯一的办法仍然是通过自己的评估进行实验。
