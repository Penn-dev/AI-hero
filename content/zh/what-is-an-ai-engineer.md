软件工程正在变化。随着 AI API 和开源模型变得可用，一个新角色出现了：**AI 工程师**。这些开发者专注于构建使用 AI 能力的应用。

这篇文章基于 Latent Space 那篇很有影响力的[《AI 工程师的崛起》](https://www.latent.space/p/ai-engineer)。所有职位名称都有不足，但有些仍然有用。那篇文章很有说服力地解释了，为什么 AI 工程师这个角色符合不断增长的市场需求。我推荐你阅读全文。

译注：本篇保留 2025 年 3 月原文对职业分工和市场的概括；它不是对当前所有公司岗位要求或薪酬的调查。API 是应用调用其他程序或服务能力的接口。

## 什么是 AI 工程师？

AI 工程师是构建 AI 应用的软件开发者。听起来也许有点吓人，但并没有那么可怕：

- 你不需要掌握线性代数或高等数学。
- 你不需要知道怎样从零构建基础模型。
- 你不需要读过《Attention is All You Need》。

你真正需要的是：

- 扎实的软件工程基础。
- 构建可靠、可扩展应用的能力。
- 对现代 AI 工具和框架的了解。
- 对用户体验和实际用途的关注。

AI 工程师把传统软件工程与人工智能连接起来。他们日常会组织 AI API 调用、实现 RAG 系统，并构建可靠的评估系统，让应用稳定工作。

他们还会用最热门的新编程语言写大量“代码”：[英语](https://x.com/karpathy/status/1617979122625712128?lang=en)。

译注：最后一句是在打趣，指用自然语言编写指令。基础模型是能用于多种任务的底层模型；RAG 是先检索相关资料再让模型生成答案的方法；评估则用一组例子和标准检查应用表现。

## AI 工程与机器学习工程

AI 工程不等于机器学习（ML）工程。它们是不同的角色，关注点和要求也不同。

可以用 API 这条分界线来理解：

- **AI 工程师**通过 API 使用 AI 模型，构建应用。
- **ML 工程师**构建这些 AI API 本身。

下面是一个简要对比：

| 方面 | ML 工程师 | AI 工程师 |
| --- | --- | --- |
| **主要关注点** | 模型训练与优化 | 用模型构建应用 |
| **专长** | 深入掌握数学、统计学和模型架构 | 扎实的软件工程基础 |
| **语言** | 仅 Python | Python 和 TypeScript |
| **教育背景** | 通常需要高等教育背景 | 软件工程背景 |
| **市场** | 高度专业化，需求很高 | 快速增长，更容易学习 |

ML 工程是一条专业化程度高的路径，需要较高的教育背景，也提供更高的报酬。ML 工程师人数很少，市场需求很大。

AI 工程更容易入门，需求也在增长。它是软件开发中增长最快的领域之一。AI 工具和 API 越来越普及，软件工程师也就比较容易转向 AI 工程。

译注：表中的“仅 Python”及教育、报酬判断都是原文的简化对比，不能理解为所有岗位的硬性规定。本次没有据此增加职业资格或薪酬承诺。

## 这不就是提示词工程吗？

但 AI 工程师难道不只是换了个好听名字的提示词工程师？这个角色究竟有多少深度？

这是一个常见误解。AI 工程师面对的复杂问题，远远不止写提示词：

- 构建能应对 AI 固有不确定性的生产级系统。
- 设计评估框架，衡量并改善系统表现。
- 建立反馈循环，让系统从用户交互中改进。
- 管理包含多个模型和 API 的复杂 AI 架构。
- 让系统保持安全，并符合隐私法规。
- 优化整个应用各个层面的成本和表现。

真正的挑战在于遵循软件工程的良好做法，构建可靠、可扩展的应用，把 AI 能力用好，而不只是写提示词。

## AI 工程师与 AI 辅助开发者

我们先澄清一个常见混淆：

- **AI 工程师**构建使用 AI 的应用，例如 ChatGPT 套壳应用或 RAG 系统。
- **AI 辅助开发者**用 Cursor、GitHub Copilot 等 AI 工具更快地写代码。

两者都使用 AI，但目的不同。前者创造 AI 应用，后者用 AI 改进自己的开发流程。

## Web 开发者能成为 AI 工程师吗？

能！Web 开发者很适合成为 AI 工程师。优秀的 Web 开发者非常关注实际交付和用户需求，这些品质在 AI 工程中同样重要。

你已有的应用开发经验，可以直接用于构建有效的 AI 系统。用户体验在 AI 工程中，与在 Web 开发中一样重要。

懂一些 Python 会有帮助，不过 TypeScript 生态发展很快，也非常适合 AI 工程。
