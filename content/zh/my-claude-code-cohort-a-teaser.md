过去几个月，我一直在打造一门完整课程，内容不止于 Claude Code 的基础用法。它是一套帮助你成为更高效的 AI 辅助开发者的方法。

下面介绍课程里有什么。

## 1. 先学基本原理，再碰 Claude Code

正式进入 Claude Code 之前，课程先讲两项重要内容：LLM 的限制，以及子智能体。这看起来有些倒着来，但我是有意这样安排的。

大多数开发者还没理解 LLM 为什么那样工作，就直接开始写 Prompt。从这里打基础，可以避免以后遇到意外结果时陷入挫败。

子智能体值得特别关注，因为它们是 Claude Code 工作方式的核心。理解它们，会影响你怎样组织任务。

## 2. 掌握核心循环：探索、构建、清空

第一天以基于代码的探索为基础，其他一切都建立在它之上。

你会学习：

- 系统地探索代码库
- 用 Claude Code 构建单项功能
- 配置对上下文用量的感知
- 有效使用计划模式
- 通过压缩来清理上下文窗口

第一天结束时，你就能交付一个完整功能。但还不知道怎样稳定地引导 Claude Code 朝自己的目标前进。

## 3. 用 AGENTS.md 和技能引导行为

第二天介绍行为引导，用它解决 LLM 的无状态问题。

语言模型不会在会话之间自行保留记忆，因此需要某种机制来引导行为。课程会教你使用 `AGENTS.md` 文件和自定义 Agent Skills。

技能把开发实践编码为可复用工具，让 Claude Code 能反复调用，帮助整个代码库保持一致。

## 4. 把大型任务拆成多阶段计划

任务超出上下文窗口时，多数开发者都会遇到瓶颈。第三天教你把大型功能拆成多个阶段。

你会学习用 PRD 描述要构建什么，再组织多阶段计划，在阶段之间清空上下文窗口。

来自《程序员修炼之道》的曳光弹方法，帮助你先做最有价值的部分，减少深陷实现细节、却始终交不出有用成果的风险。

## 5. 建立紧密的反馈循环

第四天会改变你看待代码质量的方式。

每增加一行代码，就增加一份维护负担。不能只让 Claude Code 不断处理问题，然后期待自然产生好结果。你需要反馈循环，引导智能体找到更好的方案。

课程会介绍一个 “do work” 技能，把开发循环写进流程：调试、探索、构建、运行反馈检查，以及测试。每次调用时，Claude Code 都遵循这个过程。

测试驱动开发（TDD）在这里很重要。LLM 已经从训练数据中理解了这些概念，好的提示能自然引出红灯、绿灯、重构循环。测试越好，智能体的表现也越好。

## 6. 通过 Ralph 迈向自主智能体

在本课程中，Ralph 指无需人介入，就能向仓库提交代码的自主 AI 智能体。

此前学到的内容都在这里发挥作用。行为引导、反馈循环和架构模式变得不可或缺。Ralph 之所以能自主运行，是因为反馈循环和 `AGENTS.md` 文件对它形成了有效约束。

最后一步，是把 Ralph 接到 GitHub Issue 待办队列上。你创建 Issue，智能体逐项完成。

## 7. 在重要的地方，让人重新参与

最后一天会说明，自主智能体并不能处理所有事情。

有些任务更适合人在环路中的协作方式：研究阶段让你在 Ralph 执行前作出设计判断；原型阶段帮助探索设计空间；QA 计划则在代码合入前保障质量。

你还会学习怎样设计适合 AI 智能体工作的代码库，把软件架构也作为自己开发判断力的一部分。

## 课程形式：自定进度，加上同期学习的支持

这是一门可以自行安排进度的课程，全部材料都能永久保留。同时，它又以同期训练营的方式组织，在两周内逐步发布材料。

这种混合方式效果很好。你可以参加实时答疑，也能加入 Discord，与其他正在解决相似问题的开发者交流。你不能盲目照搬一套方法，而要把它应用到自己的代码库和约束中。训练营的价值就在这里。

## 整体思路

这门课程构建的是一整套系统。多阶段计划改善 Ralph 的执行，行为引导改善代码质量，反馈循环帮助智能体找到更好的办法，各部分互相支持。

结束时，你会理解那些让 AI 辅助开发能规模化运作的软件工程原则。

如果这些内容正合你的需要，我们训练营里见。
