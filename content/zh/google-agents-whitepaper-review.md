2024 年 9 月，Google 的一群研究者发布了一份[智能体白皮书](https://www.kaggle.com/whitepaper-agents)。

这篇文章并没有特别新颖或有争议的观点。

但它很好地定义了一组与智能体有关的术语。

它解释了智能体和工具是什么，还给出了几个有意思的额外定义，我们下面会讲到。

我觉得它很适合入门，所以想带你看看。

## “智能体”的定义

先看最有意思的部分，也就是定义本身。

智能体是“一种应用，它通过观察世界，并使用手头的工具采取行动，尝试达成某个目标”。

听起来没错，但按这个定义，恒温器也算智能体。

好在白皮书还区分了智能体和模型。

其中有一张很好的对照表：

- 模型受训练数据的限制，而智能体能访问外部系统。
- 智能体能读取聊天历史，让上下文随着时间加入更多信息。

也就是说，模型本身不构成智能体。智能体是包含记忆、推理、规划和工具调用的系统。

不过，作者也没有给出特别严格的定义。引言中有个有趣的说法，他们说这些因素组合起来，“就让我们想到智能体这个概念”。

说白了，如果看起来有 `agentic` 的味道，多半就算智能体。

译注：agentic 在这里指表现出自主行动的特征。上面的恒温器例子和宽泛定义之评议，都是原作者的观点。

## 协调层

白皮书还谈到，协调层对智能体很重要。

它管理智能体怎样“接收信息、进行内部推理，并用推理结果指导下一次决定或行动”。

换句话说，就是我在 [Vercel AI SDK 教程](/agents-with-vercel-ai-sdk?list=vercel-ai-sdk-tutorial)里介绍过的反馈循环（[英文原文](https://www.aihero.dev/agents-with-vercel-ai-sdk?list=vercel-ai-sdk-tutorial)）。

## “工具”的定义

不过，几乎所有人都同意，要让系统具有 `agentic` 特征，它就必须能使用工具。

白皮书把工具定义为“连接智能体内部能力与外部世界的桥梁”。

它还进一步区分了两种工具：扩展与函数。

### 扩展

扩展用于增加智能体的能力。白皮书举的例子是调用 API，比如查询天气，或查询两地之间的路线。

你可以把扩展理解为智能体不必先询问就能执行的事情。

它们类似常见的工具定义。我们通过示例说明每个工具的用法，并告诉智能体，成功调用需要哪些参数。

译注：“不必先询问”是这份白皮书中的分类说明，不代表任何具体系统已经取得执行操作或分享信息的许可。应用仍需要自己的授权和权限控制。

### 函数

函数与扩展不同。你教 LLM 怎样使用它们的方法相同，但调用工具的控制权在用户，而不是智能体。

比如删除数据库里的一条帖子。部署智能体的系统，可能根本没有删除权限；出于各种原因，你也可能不愿把权限给它。

所以，智能体不自己删除，而是告诉用户：“delete this post.”

中文理解：删除这条帖子。

这就是白皮书所说的函数：“调用实际 API 入口的逻辑和执行工作，从智能体转交回客户端应用”。

这样做可能有几个原因：

- 和前面一样，你不想赋予智能体执行这些操作的权限。
- 你希望加入人的审核。
- 或者，构建智能体时想复用现有 API 入口。

总结一下：扩展由智能体负责执行工具，函数由客户端负责执行工具。

### 我的看法

这个定义有点奇怪。我总觉得，把概念挂在已经很常用的词上会带来问题。开发者本来就知道“函数”是什么，而这里函数与扩展的区别又不太清楚。

白皮书后面提到了 Google Vertex AI 平台，所以，函数和扩展也许是那个平台里的一组重要概念。

我喜欢把它当教学上的区分方法，但还不确定自己会不会采用这套定义。

## 总结

总体来说，Google 这份白皮书很适合入门，也给讨论增加了几个有意思的定义。

里面还有 LangChain 和 Python 的示例，值得自己看看。
